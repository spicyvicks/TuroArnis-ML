# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: `estimate_stick_from_pose()` causes label leakage — The function receives `class_idx` (ground-truth label) and branches on it to pick a hardcoded stick direction. During both training AND test feature extraction, the true label is used to inject fake geometry. This is not generalizable to inference.
- [ ] CONSTRAINT: `global_mean_pool` averages ALL nodes including fake stick nodes — Even when `has_stick_nodes=False` removes edges to stick nodes, the node feature tensor `x` still contains 35 rows. `global_mean_pool(x, batch)` computes the unweighted mean of all 35 rows, including the 2 fake stick nodes. In v5, those nodes were `[0,0,0,0,0.7,225]` (non-zero `dist_to_hip` and `angle_from_hip` computed from origin), which created a constant offset the model learned to compensate for. In v6, the estimator injected different wrong positions per class, actively shifting the embedding.
- [ ] CONSTRAINT: More synthetic data amplifies failure modes — 3x synthetic generation from zero-stick parents creates 2 synthetic copies with the same corrupted geometry per real sample. The model overfits to these artifacts. v5 1x (no synthetic) achieved 48.7%, v5 3x achieved 77.7%. The sweet spot is likely 2-3x but ONLY if parent stick geometry is valid.
- [ ] CONSTRAINT: `compute_hybrid_features()` leaks the true label — It uses `key = f"{viewpoint}_{class_name}"` where `class_name` is the ground-truth label to pick the template. This means hybrid features encode "how similar am I to my own class template?" — unusable in production and creates circular training signal.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Label-conditioned feature generation | Using `class_idx`/`class_name` inside feature extraction (estimator, hybrid template lookup) makes features oracle-dependent and non-generalizable | blocking | All feature extraction must be label-agnostic; use body-pose-only heuristics or raw geometry |
| `global_mean_pool` with masked nodes | Removing edges (`has_stick_nodes=False`) does NOT remove nodes from pooling; fake nodes still contaminate the graph embedding | blocking | Use `node_mask` with zero-multiplication before pooling, or reduce node count dynamically |
| Synthetic amplification of bad parents | Generating 3x synthetic from zero-stick/estimated-stick parents multiplies corrupted geometry in training set | advisory | Skip synthetic generation for samples with `has_stick_nodes=False`, or cap synthetic multiplier at 1x for these classes |
| Aspect-ratio bug in stick normalization | Estimator normalizes stick X by `img_width` and Y by `img_height` separately, distorting stick angle in non-square images | advisory | Use single scale `max(img_width, img_height)` or compute all geometry in normalized coordinates from the start |

- crown: 73.3%, left_chest: 33.3%, left_elbow: 20.0% (these 3 are the problem)
- All right-side classes: 80-92%

**What failed:** v6 stick estimator dropped overall to 74.1% and left_chest to 0.0%.

**Audit conclusion:** The estimator injects label-conditioned wrong geometry that `global_mean_pool` averages into the embedding, destroying body-pose-only learning. The zero-stick fallback (v5) works better because fake nodes have predictable constant offsets the model compensates for.

**Option A hypothesis:** If we make zero-stick nodes TRULY zero (all 6 dims = 0) AND mask them out of `global_mean_pool`, the model will rely purely on body-pose features (which already achieve 77.7% with the constant-offset v5). The new signed features (`left_wrist_x_signed`, `right_wrist_height_signed`, etc.) from v6 should then push accuracy to 80-85%.

## Decisions Made

- **Estimator is dead** — `estimate_stick_from_pose()` will NEVER be called again. It is 200 lines of label-leaked garbage.
- **Zero-stick fallback is the correct path for front view** — Stick detection fails frequently in front view (end-on orientation). The model must classify from body pose + hybrid features alone for ~30-50% of front-view samples.
- **Signed features are kept** — `left_wrist_x_signed`, `right_wrist_height_signed`, etc. were added in v5/v6 and should help body-pose discrimination even without stick nodes.
- **Real-only validation** — Synthetic test data was inflating validation accuracy and causing early stopping to optimize for a mirage. Validation must be pure real test data.
- **3x synthetic is the starting point** — v5 3x gave 77.7% (best so far). If Option A doesn't beat this, try 1x or 2x.
- **Front-view goal is 80%+ real-only** — 77.7% is close; with true zero nodes + masked pooling + signed features, 80-85% is the target.
