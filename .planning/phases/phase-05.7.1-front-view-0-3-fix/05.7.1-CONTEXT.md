# Phase 5.7.1: Front View Classes 0-3 Stick Detection Fix - Context

**Gathered:** 2026-04-23
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix the arnis stick detection rejection problem specifically for **front viewpoint classes 0-3** (crown_thrust_correct, left_chest_thrust_correct, left_elbow_block_correct, left_eye_thrust_correct). In the front view, the stick appears as a small dot/end-on view, causing the current detection logic to reject most training samples for these classes.

**Scope:** Modify feature extraction logic only - no model architecture changes, no other viewpoints, no other classes.

**Success Criteria:** Front view classes 0-3 training samples are accepted and processed with fallback stick estimation using MediaPipe landmarks.

</domain>

<decisions>
## Implementation Decisions

### Scope: Which Classes/Viewpoints

- **D-01:** **Front view classes 0-3 only**: crown_thrust_correct (0), left_chest_thrust_correct (1), left_elbow_block_correct (2), left_eye_thrust_correct (3)
- **D-02:** **All other combinations unchanged**: Front view classes 4-12, all left/right viewpoint classes - keep current 0.15 stick confidence threshold and skip behavior

### Missing Stick Handling Strategy

- **D-03:** **Allow samples through**: For front view classes 0-3, allow feature extraction to proceed even when YOLO stick detector returns no keypoints
- **D-04:** **Use MediaPipe pinky as grip**: When stick detection fails, use the MediaPipe pinky landmark (index 17 for left hand, 18 for right hand) as the stick grip position
- **D-05:** **Same-hand finger fallback chain**: If pinky is not visible/low confidence, fallback to other fingers from the same hand (agent discretion: index → middle → ring finger in order of preference)
- **D-06:** **Skip if no hand visible**: If no fingers from the correct hand are visible, skip the sample (maintains data quality guardrail)

### Tip Position Estimation

- **D-07:** **Agent discretion**: When using pinky/finger fallback as grip, estimate tip position using:
  - Body orientation (use existing Method 4 logic from `apply_stick_method4_correction`)
  - Shin-based stick length calculation
  - Project outward from grip in estimated stick direction

### Configuration Approach

- **D-08:** **Hardcoded behavior**: Logic is hardcoded specifically for front view + classes 0-3 combination
- **D-09:** **No external config**: No YAML/JSON configuration parameter - the behavior is intrinsic to these specific classes in front view

### Monitoring and Logging

- **D-10:** **Log counts per class**: Track how many samples were processed with missing stick detection per class (for monitoring data pipeline health)
- **D-11:** **No individual image logging**: Don't log individual image paths (keeps logs manageable)

### Validation Rules

- **D-12:** **Relaxed only for stick**: All other validation rules remain strict (pose detection, wrist visibility, physical plausibility)
- **D-13:** **Mark in metadata**: Flag samples that used the fallback method so they can be analyzed separately if needed

### the agent's Discretion

- Exact finger fallback priority order (index, middle, ring) when pinky unavailable
- Tip position projection algorithm details (reuse existing Method 4 projection logic)
- Whether to apply foreshortening handling differently for these fallback cases
- Exact log message format and location

</decisions>

<specifics>
## Specific Ideas

- Leverage existing Method 4 correction logic in `2b_generate_node_hybrid_features.py` - specifically the `apply_stick_method4_correction` function already has pinky-based anchoring
- The foreshortening check (40px threshold) should still apply even for fallback cases - if the raw stick would have been rejected as foreshortened, the fallback grip should still be used
- Class 0-3 are all "thrust" or "block" techniques where the stick is often pointing toward/away from camera in front view, making detection inherently harder

</specifics>
