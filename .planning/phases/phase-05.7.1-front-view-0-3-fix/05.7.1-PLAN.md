# Phase 5.7.1: Front View Classes 0-3 Stick Detection Fix - Plan

## Objective

Modify the feature extraction pipeline to allow training samples from front view classes 0-3 (crown_thrust_correct, left_chest_thrust_correct, left_elbow_block_correct, left_eye_thrust_correct) to pass through even when YOLO stick detection fails. Use MediaPipe pinky/finger landmarks as fallback grip estimation.

## Background

**Problem:** In front view, the stick appears as a small dot/end-on, causing YOLO stick detector to fail. Current logic rejects these samples, causing data starvation for classes 0-3.

**Solution:** Implement fallback logic for front view + classes 0-3 only:
- Use MediaPipe pinky (index 17/18) as grip when stick detection fails
- Fallback chain: pinky → index → middle → ring (same hand)
- Estimate tip using existing shin-based projection logic

3. **Add fallback logic (around line 228-231):**
   ```python
   # Current: returns None if no stick detected
   
   # New logic:
   FRONT_VIEW_0_3_CLASSES = [0, 1, 2, 3]  # crown, left_chest, left_elbow, left_eye
   
   if (viewpoint == 'front' and 
       class_idx in FRONT_VIEW_0_3_CLASSES and 
       (stick_results.keypoints is None or len(stick_results.keypoints.data) == 0)):
       
       # Use pinky/finger fallback
       stick_grip, stick_tip = estimate_stick_from_fingers(kpts, results.pose_world_landmarks.landmark, w, h)
       
       if stick_grip is None:
           return None  # No fingers visible, skip
           
       # Log fallback usage
       print(f"[FRONT_0-3_FALLBACK] Using finger fallback for {image_path.name}")
       
   else:
       # Original logic - skip if no stick
       return None
   ```

4. **Create helper function `estimate_stick_from_fingers()`:**
   - Use same-hand finger priority: pinky (17/18) → index → middle → ring
   - Use existing `apply_stick_method4_correction` for tip projection
   - Return None if no fingers visible
